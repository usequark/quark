# Security Policy

Quark takes security reports seriously. This document describes how to report a
vulnerability and what happens after you do.

For an overview of the security features Quark ships with (rate limiting, headers,
auth, storage, environment handling), see [docs/SECURITY_FEATURES.md](docs/SECURITY_FEATURES.md).
That document is a feature guide, not a reporting channel.

## Supported Versions

Quark is pre-1.0. Only the current release line of each published package receives
security fixes.

| Package | Supported |
|---|---|
| `@usequark/quark-core` | Latest `2.x` on `main` |
| `@usequark/quark-create-app` | Latest `1.x` on `main` |

Applications you scaffold are yours to maintain. The CLI can pull in updates
(`npx @usequark/quark-create-app update`), but patching a generated app after
you have customised it is your responsibility.

> The npm scope migrated from `@techstream/*` to `@usequark/*`. The old scope
> still resolves and remains installable; prefer `@usequark/*` for anything new.
> This does not change how you report a vulnerability.

## Reporting a Vulnerability

**Do not open a public GitHub issue, discussion, or pull request for a security
problem.** A public report gives every attacker a head start.

Use **GitHub Private Vulnerability Reporting** — the most direct route:

> <https://github.com/usequark/quark/security/advisories/new>

If private reporting is unavailable to you, open a regular issue that contains
**only** the words `security report` and nothing else, and a maintainer will
contact you privately. Do not include technical detail in that issue.

Please include as much of the following as you can:

- Type of issue (e.g. injection, auth bypass, path traversal, secret exposure)
- Affected package and version (`@usequark/quark-core@2.4.3`)
- Steps to reproduce, ideally a minimal reproduction
- Proof-of-concept or a request/response trace with secrets redacted
- Impact — what an attacker gains, and what they need in order to reach it
- Whether any real user data is at risk
- Suggested remediation, if you have one

### What to expect

| Stage | Target |
|---|---|
| Acknowledgement | 3 business days |
| Triage and severity assessment | 10 business days |
| Fix released for critical/high | 30 days from triage |
| Fix released for medium/low | Next scheduled release |
| Public disclosure | Coordinated with you, 90 days minimum after a fix ships |

Severity is assessed on real impact to a running Quark application, not on the
theoretical worst case. We will keep you updated while we work on it and will
credit you in the advisory unless you prefer otherwise.

## Scope

**In scope**

- `@usequark/quark-core` and `@usequark/quark-create-app`, as published
- The default application layout generated by the CLI (`apps/web`, `apps/worker`,
  `packages/db`, `packages/config`, `packages/ui`, `packages/jobs`)
- The repository's CI/CD configuration in `.github/workflows/`
- The scaffold templates in `packages/cli/templates/`

**Out of scope**

- Third-party dependencies — report those to their maintainers; we will help
  coordinate an upgrade if it affects us
- Applications generated by Quark and then modified — those are your code now
- Findings that require an already-compromised host, or physical access
- Denial-of-service findings against a development machine
- Missing hardening headers on a server the user has not deployed to
- Reports generated solely by an automated scanner with no demonstrated impact

## Secret Exposure

If you have accidentally committed a secret to this repository:

1. **Rotate the credential first.** Assume anything committed is compromised,
   even if the commit was reverted.
2. Report it privately using the channel above, without including the secret
   itself.
3. If the commit was ever pushed to a public branch or fork, treat the rotation
   as mandatory rather than precautionary.

We will remove the offending content from history on request. See
[docs/SECURITY_FEATURES.md](docs/SECURITY_FEATURES.md) for a secret-rotation
runbook covering `NEXTAUTH_SECRET` and database credentials.
