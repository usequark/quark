Brief

Build a Link-in-Bio application. A single-page profile where someone can display their links, bio, and avatar. Think Linktree, but simpler. The app has three pages:

Page Purpose
Landing Describe the product. Explain what it does. Encourage someone to create their own page.
Create A form to set up a profile: name, bio, links, avatar image. Returns a shareable URL and edit code.
Bio The public-facing profile page. Displays avatar, bio, and links. Clean, fast, mobile-friendly.

Target audience: Industrial and trades clients (builders, electricians, landscapers) who need a simple mobile-friendly page to consolidate their links for customers. Think a tradie sharing their Instagram, Google Maps listing, website, and booking link in one place. Design for trust, fast loading, and clarity over flashy visuals.

Work locally. No deployment required.

Technologies

The scaffold uses several technologies you may not have encountered. Here is what you need to know about each one to complete this task.

Next.js

Next.js is a web framework built on React. Pages are files inside apps/web/src/app. The URL path matches the file structure: app/page.js becomes /, app/about/page.js becomes /about. Dynamic segments use square brackets: app/[slug]/page.js becomes /anything-here and app/services/[service]/page.js becomes /services/any-service.

A page is a function that returns JSX (HTML-like syntax in JavaScript). Pages can be async and fetch data directly:

export default async function Page({ params }) {
  const data = await getData(params.slug)
  return <div>{data.name}</div>
}

React

React is a library for building user interfaces with reusable pieces called components. Components accept inputs called props (like function arguments). JSX lets you write HTML tags inside JavaScript. The scaffold uses React Server Components, which are async functions that run on the server and can fetch data directly from the database.

Example component usage:

import { Button, Card } from "@techstream/quark-ui"

export default function MyPage() {
  return (
    <Card>
      <h1 className="text-xl">Hello</h1>
      <Button href="/create">Get Started</Button>
    </Card>
  )
}

Prisma & PostgreSQL

Prisma is a database toolkit. You define your data models in schema.prisma and it generates a client for querying the database. After adding a model, run pnpm db:generate to update the client, then pnpm db:migrate to create the actual table in PostgreSQL.

Querying the database from a page:

import { db } from '@techstream/quark-core/db'

const profile = await db.profile.findUnique({
  where: { slug: 'my-tradie' }
})

Other useful queries:

  • findMany() (list),
  • create() (insert),
  • update() (modify),
  • delete() (remove).

Redis Caching

Cache the bio page data in Redis so frequent visitors get a fast response without hitting the database every time. Invalidate the cache when the profile is updated. Decide your TTL (time-to-live) and eviction strategy.

Note on Next.js caching: Next.js has built-in data caching that may reduce the need for Redis on a single-server app. However, Redis gives you explicit control over cache lifetime and invalidation, and is essential knowledge for multi-server deployments. Consider this exercise a learning opportunity rather than a performance necessity.
What is Redis: Redis is an in-memory key-value store. Data lives in RAM, so reads are near-instant. It is useful for caching data that is read frequently but changes infrequently, like a public profile page.
Getting started: The scaffold provides a cache client. Import it and use these three operations:
import { cache } from '@techstream/quark-core/cache'

// Save to cache (expires in 1 hour)
await cache.set('profile:my-slug', profileData, { ttl: 3600 })

// Read from cache
const data = await cache.get('profile:my-slug')

// Delete from cache (on profile update)
await cache.del('profile:my-slug')

Here is an example implementation pattern for the bio page:

export default async function BioPage({ params }) {
  const cacheKey = `profile:${params.slug}`

  // 1. Try cache first
  let profile = await cache.get(cacheKey)

  // 2. If not cached, query database
  if (!profile) {
    profile = await db.profile.findUnique({
      where: { slug: params.slug }
    })
    if (!profile) return <div>Not found</div>

    // 3. Store in cache for next time
    await cache.set(cacheKey, profile, { ttl: 3600 })
  }

  return <div>{profile.name}</div>
}

When the profile is updated (via the edit page), delete the cache key so the next read fetches fresh data. This is called cache invalidation and is the hardest problem in caching. For this app, deleting the specific key on update is sufficient.

UI Polish & Responsive Design

Make the app work well on mobile and desktop. Choose a colour palette and typography. Consider what makes a Link-in-Bio page feel professional vs generic.

What is a component: Components are reusable pieces of UI. The scaffold provides shared components in packages/ui/src including Button, Card, and a base layout. Browse that directory to see what is available. Import them in your pages:
import { Button, Card } from "@techstream/quark-ui"

export default function LandingPage() {
  return (
    <Card className="max-w-lg mx-auto mt-8 p-6">
      <h1 className="text-2xl font-bold mb-4">Your Links, One Page</h1>
      <p className="text-gray-600 mb-6">Share all your important links in one place.</p>
      <Button href="/create">Create Your Page</Button>
    </Card>
  )
}
Tailwind for responsive design: Tailwind uses breakpoint prefixes. text-lg applies at all sizes. md:text-xl applies only at medium screens and up. Build mobile-first: start with the mobile layout, then add md: and lg: overrides. Standard breakpoints: sm (640px), md (768px), lg (1024px).
Design brief reminder: Your target audience is tradespeople. Large touch-friendly buttons, readable font sizes, fast loading, clear hierarchy. Avoid clutter. A bio page should communicate trust in under 3 seconds.

Branding & User Customization

Give the application a name and consistent visual identity. Create a simple logo (AI tools, Canva, or inline SVG). Apply it across all pages. Let users choose a background colour, accent colour, or layout variant when creating their profile. Store the preference and apply it on the bio page.

Getting started: Pick a name and colour palette first. Apply via Tailwind classes or CSS variables. For user customization, store colour choices in the Profile model and apply dynamic styles using inline styles or Tailwind's style prop. Example: store bgColor: "#1a1a2e" in the database, then use style={{ backgroundColor: profile.bgColor }} on the bio page wrapper.

Analytics

Track link clicks on bio pages. Store counts in Postgres or Redis. Optionally display click totals on the page or in a simple dashboard.

Getting started: Wrap each link click in a simple API call or Server Action that increments a counter. Add a click_count field to your link model or store in Redis with await cache.incr('clicks:profile-slug:link-url'). Display the total on the bio page or add a separate stats page at /[slug]/stats.
